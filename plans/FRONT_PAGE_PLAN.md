### 1-1. 왜 긴장 곡선이 레벨 디자인 안으로 가는가

긴장 곡선 3장은 무릉·가마솥·여우숲을 같은 자로 잰 **레벨 평가**다. "레벨디자인끼리 모아라"(피드백 7)의 직접 적용 대상이다.
지금처럼 기획서 모음 꼬리에 달려 있으면 레벨 덩어리가 세 군데로 흩어진다.

### 1-2. 왜 무릉만 역기획에서 떼어내는가

피드백 3(제작/역기획 분리)과 피드백 7(레벨 모으기)은 무릉에서 충돌한다 — 무릉은 역기획서이면서 레벨 디자인이다.
**피드백 7을 우선**한다: 레벨 디자이너 직군으로 보실 때 언리얼 제작과 무릉이 붙어 있어야 한 사람의 역량으로 읽힌다.
대신 무릉 카드에는 `역기획서` 배지를 크게 달아 성격을 잃지 않게 한다. 역기획 섹션 lede에도 "레벨 역기획서는 위 레벨 디자인 섹션에 ↑" 한 줄을 둔다.

## 3. 이력서 확대 연출 (피드백 5)

### 3-1. 연출 정의

요약 카드가 "커져서" 전체 이력서가 되는 것처럼 읽히게 한다. 실제 DOM morph는 하지 않는다 — 벤토 6패널을 FLIP으로 옮기는 것은 모바일에서 깨질 위험이 크고, 얻는 것보다 잃는 것이 많다.

**대신 두 장치로 같은 인상을 만든다.**

1. **동형 반복** — 전체 이력서 Profile 카드가 요약 카드와 **같은 구성**(사진 → 이름 → 스탯 타일 → 학력)을 더 큰 크기로 반복한다. 눈이 "같은 카드가 커졌다"로 읽는다. 현재 `.rz-id`는 이미 사진+이름+스탯 구조라 스탯 항목만 맞추면 된다.
2. **진입 스케일** — `#resume`가 뷰포트에 20% 들어오면 `.is-open` 부여 → `.rz-card`들이 `scale(.955) translateY(20px) opacity(0)` → `scale(1) translateY(0) opacity(1)`. 카드 인덱스별 40ms stagger, duration 620ms `cubic-bezier(.2,.7,.25,1)`. **1회성**(되감지 않음 — 스크롤 왕복 시 깜빡이면 싸구려로 보인다).

### 3-2. 구현 방식

- 기본: `IntersectionObserver` 1회 토글. 전 브라우저 동작.
- 향상: `@supports (animation-timeline: view())`에서만 요약 카드가 스크롤에 맞춰 `scale(1→1.04)` + 페이드아웃하는 스크럽을 추가. 미지원 브라우저는 이 레이어만 빠지고 나머지는 동일.
- `prefers-reduced-motion: reduce` → 변환 없이 즉시 최종 상태. `no-JS` → `.is-open` 기본 적용(CSS에서 `.rz:not(.js) .rz-card{opacity:1}` 형태로 안전 폴백).

### 3-3. 요약 ↔ 전체 스탯 정합

전체 이력서 Profile의 스탯 타일도 **요약과 같은 4개**로 교체한다. 지금은 `기획 문서 5 · 팀 게임 제작 4 · 수상 4 · 라이브 서비스 1`이라 요약과 숫자가 어긋난다.

| 위치 | 현재 | 변경 |
|---|---|---|
| `.rz-stats` | 기획 문서 5 / 팀 게임 제작 4 / 수상 4 / 라이브 서비스 1 | **게임 프로젝트 5 / 게임 서비스 2 / 역기획서·제안서 4 / 수상 4** |
| 푸터 `.fine` | 프로젝트 기획서 2 · 역기획서 2 · 제안서 1 | 제작 프로젝트 2 · 역기획서 2 · 제안서 1 · 언리얼 레벨 3 |
| `#projects` h2 | 5개 프로젝트 | 섹션 분리로 문구 재작성 |

## 4. 섹션 재구성 상세

### 4-1. `#leveldesign` (신설)

```

      그리고 셋을 같은 자로 다시 잰 긴장 곡선.

── 제작 · 언리얼 ──────────  (기존 #unreal 내용 그대로: MAP 01/02/03 + ulab-foot)

- 기존 `#unreal` id는 **앵커 호환을 위해 유지**한다(이력서 엔진 배지 · FPS 자습 행 · 관리자 시드가 참조). `<section id="leveldesign">` 안의 언리얼 블록에 `id="unreal"`을 남긴다.
- `#tension` id도 그대로 유지(목차·긴장곡선 앵커).

```
Reverse-engineered                    ← .tag

### 4-4. `#showcase` — 캐러셀 (맨 아래)

- `<header class="cr-hero">` → `<section class="cr-hero cr-hero--foot" id="showcase">`. **클래스명·내부 구조·마커는 그대로 둔다** — 관리자 CAROUSEL/CAROUSEL_BG 마커와 3D 로직이 그 구조에 묶여 있다.
- 높이 `100svh` → `min-height:min(78svh,720px)`. 하단 스크림은 푸터(`--surface-2`)로 수렴하도록 스톱 재조정.
- 상단에 `.tag` `Showcase` + h2 `프로젝트 훑어보기` + lede 한 줄 추가.
- **`.cr-kick`(히어로 문장) 블록은 여기서 제거**하고 새 히어로로 이관.

### 4-5. JS 수정점 (캐러셀 이동에 따른)

| 파일·위치 | 현재 | 변경 |
|---|---|---|
| 캐러셀 IIFE `heroReady` | `hero-rotation-done` 이벤트 대기 | **`true`로 시작**. 자동 넘김은 IntersectionObserver(`threshold .4`)가 이미 "보일 때만" 제어하므로 맨 아래에서도 정상 |
| 목차 바 `is-scrolled` | `scrollY > innerHeight - 80` | 새 히어로 엘리먼트 높이 기준(`heroEl.offsetHeight - 80`)으로 |
| `.cr-hero` keydown ←/→ | 그대로 | 그대로 (섹션 포커스 시 동작) |
| 히어로 문장 회전 IIFE | `revealArrows()`가 `hero-rotation-done` 발신 | 발신 유지(무해). 새 히어로 안에서 동작 |
| `.cr-scroll` idle 토글 | 캐러셀 히어로 하단 | 새 히어로 하단으로 셀렉터만 이동 |

## 5. 관리자 마커 설계 (신규 2쌍)

> ⚠️ **`portfolio-admin`이 이 PC에 없다.** CLAUDE.md §2-24의 관리자 사이트는 macOS 환경 기록이고, 이 Windows PC의 `find` 결과 해당 폴더가 없다.
> 따라서 **이번 구현은 index.html 쪽 마커까지만** 심고, 관리자 백엔드·UI 수정은 아래 사양으로 남긴다. 관리자가 있는 환경에서 이 사양대로 반영하면 붙는다.

### 5-1. `ADMIN:HERO_STATS`

요약 이력서의 수치 4개 + 학력 줄 + 꼬리 줄.

```html
<!-- ADMIN:HERO_STATS START -->
<div class="hz-stat hz-stat--big"><b>5</b><span>게임 프로젝트 경험</span></div>
<div class="hz-stat hz-stat--big"><b>2</b><span>게임 서비스 경험</span></div>
<div class="hz-stat"><b>4</b><span>역기획서 · 제안서</span></div>
<div class="hz-stat"><b>4</b><span>수상</span></div>
<p class="hz-edu"><span class="rd">2026.02</span>숭실대학교 IT글로벌미디어학부 졸업</p>
<p class="hz-more">동아리 3 · 대외활동 7 · 자격증 4 · 장학 3 — 전체 이력 아래로 ↓</p>
<!-- ADMIN:HERO_STATS END -->
```

관리자 필드: `label`·`value`·`big`(bool) 반복 + `edu_date`·`edu_text` + `more_text`.

### 5-2. `ADMIN:HERO_BUTTONS`

버튼 그리드 **양쪽 모드를 함께** 담는다. 토글은 CSS/JS가 `data-mode`로 전환하므로 마크업은 한 번만 생성한다.

```html
<!-- ADMIN:HERO_BUTTONS START -->
<div class="pbtn-set" data-mode="role">
  <p class="pbtn-g">레벨 디자인</p>
  <a class="pbtn" href="#leveldesign">
    <span class="pbtn-b pbtn-b--make">제작</span>
    <span class="pbtn-b pbtn-b--sub">3D · 언리얼</span>
    <b class="pbtn-t">언리얼 레벨 제작 3종</b>
  </a>
  …
</div>
<div class="pbtn-set" data-mode="engine" hidden> … </div>
<!-- ADMIN:HERO_BUTTONS END -->
```

관리자 데이터 모델(`hero_button` 섹션):

| 필드 | 타입 | 설명 |
|---|---|---|
| `title` | text | 버튼 제목 |
| `href` | text | 링크 (내부 앵커 또는 projects/*.html) |
| `kind` | select | 제작 / 역기획서 / 제안서 |
| `sub` | text | 원작 게임명 또는 엔진 표기 |
| `status` | select | (없음) / 서비스 중 / 서비스 종료 |
| `role_group` | select | 레벨 디자인 / 시스템·콘텐츠·밸런스 / 퀘스트 / 캐릭터 |
| `engine_group` | select | 2D · MSW / 3D · Unity / 3D · 언리얼 / 역기획서 |
| `order` | int | 그룹 내 순서 |

`renderers.ts`에 `renderHeroButtons()`를 추가해 `role_group`·`engine_group`으로 두 번 그룹핑하여 2세트를 출력한다. 그룹 순서는 위 표 순서 고정(레벨 디자인이 항상 먼저).

### 5-3. 기존 마커 영향

| 마커 | 영향 |
|---|---|
| `CAROUSEL`, `CAROUSEL_BG` | **위치만 문서 하단으로 이동.** 내용·publish 로직 무영향 |
| `PROJECTS` | 섹션이 둘로 쪼개지므로 마커도 `PROJECTS_BUILT` / `PROJECTS_REVERSE` 2쌍으로 분할 필요. 무릉 카드는 `UNREAL` 마커 뒤 별도 `PROJECTS_LEVEL` 마커로 이동 |
| `UNREAL`, `REVIEWS`, `SKILLS`, `RESUME_*`, `PLAY`, `YT` | 무영향 |
| `FOOT_COUNTS` | 문구만 갱신 |

시드(`seed-data.ts`)도 새 스냅샷으로 갱신해야 한다 — 관리자 환경에서 함께.
