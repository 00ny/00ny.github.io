# 방지턱 개편 설계서 (v2 · 확정)

> **상태: 사양 확정. 구현 착수 가능.**
> 근거가 된 피드백 — 인사담당관: *"현재 화면이 너무 복잡하다. 또한 사람 특성상 아래로 내려갈 수밖에 없는데, 아래 또한 너무 복잡하다."*

## 0. 목적과 전제

**목적**
1. 첫 화면의 정보량을 최소화한다.
2. 의도된 지점에 **방지턱**을 두어, 아래가 중복 내용임을 먼저 알려 드리고 한 번 쉬어 가게 한다.

**전제**
- **이 사이트를 여는 분은 이미 이력서를 보고 오신다.** 그래서 `이력 · 활동`은 이미 확인하신 내용의 재확인에 가깝고, 여기서는 뒤로 둔다.
- 화면은 **방지턱 위 / 아래**로 나뉜다.

**원칙** — 방지턱 위는 *덜어내서*, 아래는 *감춰서* 가볍게 만든다. 둘은 다른 수단이며 섞지 않는다.

## 2. 방지턱 (확정)

```
┌─────────────────────────────┐
│         캐러셀 (마지막)        │
└─────────────────────────────┘
              ↓
      ┌───────────────┐
      │  + 더 보기      │   ← 페이지는 여기서 끝난다
      └───────────────┘
              ↓ 클릭
   "아래는 '중복 내용'입니다.
    다만, 더 편하게 볼 수 있도록 준비하였습니다."
              [ 열기 ]  [ 아니요 ]
              ↓ 열기
      아래 5개 영역이 나타나고 목차에 항목이 추가된다
              ↓
      맨 끝에 [ 접기 ] — 누르면 다시 닫히고 방지턱 위치로 돌아온다
```

| 항목 | 확정 사양 |
|---|---|
| 감추는 방식 | **DOM 유지 + 감춤** (제거 아님) |
| 스크롤 가로채기 | **하지 않는다.** 스크롤을 막지 않고, 페이지가 여기서 한 번 끝나도록 둔다 |
| 확인 | 모달 아님 — 그 자리에 펼쳐지는 한 줄 + 버튼 2개 |
| 확인 문구 | `아래는 '중복 내용'입니다. 다만, 더 편하게 볼 수 있도록 준비하였습니다.` |
| 접기 | **필요.** 열린 영역 끝에 `접기` 배치, 누르면 방지턱 위치로 스크롤 복귀 |
| 기억 | **하지 않음.** 새로고침하면 다시 닫힌 상태 |

**감추는 방식이 무게에 주는 영향** — 감춰진 영역의 이미지는 전부 지연 로딩이라, 화면에 들어올 일이 없으면 **받지 않는다.** 즉 DOM 에 남겨도 첫 로딩은 사실상 그대로다(직전 최적화로 확보한 1.6초 유지). 검색엔진은 계속 읽을 수 있다.

**접근성 요건**
- `더 보기`·`열기`·`아니요`·`접기` 전부 `<button>`
- 열림 상태를 `aria-expanded` 로 노출, 감춤은 `hidden` 계열로 접근성 트리에서도 제거
- 열면 첫 섹션 제목으로 포커스 이동, 접으면 `더 보기` 로 포커스 복귀

### 3-5. 유튜브 (지시 7)

**문제** — 갈래 헤더 `.ytb-gh` 의 `::after` 가 `flex:1` 이라 남은 폭 전체를 가로선으로 채운다. 그 선이 쇼츠 레일 위까지 뻗어 공간을 낭비한다.

```
현재                              변경 후
┌──────────┬────────┐          ┌──────────┬────────┐
│ 인게임─────────────│          │ 인게임──── │        │
│ [카드][카드]  쇼츠  │          │ [카드][카드]│  쇼츠   │
│ 포폴───────────────│          │ 포폴────── │  (확대) │
│ [카드][카드]       │          │ [카드][카드]│        │
└──────────┴────────┘          └──────────┴────────┘
   선이 쇼츠 위까지 침범            선은 카드까지만
```

- 선을 **영상 카드 오른쪽 끝**에서 끊는다
- 회수한 폭을 **쇼츠 레일에 배분**
- 쇼츠 높이 = **왼쪽 영역 전체 높이와 동일**, 그 안에서 **9:16 유지 최대 크기**
- 쇼츠에 **조회수 `9만`** 표기 추가

### 3-6. 업데이트 띠 (지시 8)

- **첫 화면과 다음 화면의 정확한 정중앙**

### 3-7. 첫 화면 좌우 페이드아웃 (지시 10)

좌측(요약 이력서)만 사라지던 것을 **우측(프로젝트 버튼 패널)에도 동일 적용.** 같은 진행도·같은 곡선으로 좌우가 함께 사라진다.

**파생 정리** — 좌측 페이드는 *"요약 이력서와 전체 이력서는 한 화면에 동시에 존재할 수 없다"* 는 배타 연출의 절반이었다. 이번 개편으로 **전체 이력서가 방지턱 아래로 내려가** 짝이 사라지므로, 배타 연출은 근거를 잃고 좌우 페이드는 **단독 연출**로 남는다. 배타를 위해 넣었던 계산(가시 구간 서로소 검증 등)은 정리 대상.

### 3-8. 첫 화면 `이력 · 활동` 링크 (파생)

대상이 방지턱 아래라 클릭해도 닿지 않는다 → **링크 제거.** 텍스트는 남기고 앵커만 없앤다.

## 5. 확인 문구 — 확정 (원안 그대로)

> 아래는 '중복 내용'입니다. 다만, 더 편하게 볼 수 있도록 준비하였습니다.

`Tool` 과 `이력 · 활동` 은 위쪽에 없는 고유 내용이라 엄밀히는 중복이 아니다. 그럼에도 이 문구를 쓰는 것은 **의도된 선택**이다 — 전제가 *"이미 이력서를 보고 오신다"* 이므로 그 두 영역은 이미 확인하신 정보의 재확인에 가깝고, **열지 않으셔도 핵심은 이미 보셨다는 것을 알려 드리는 것이 이 안내의 목적**이다. 문구를 더 두루뭉술하게 다듬으면 "열지 않아도 괜찮다"는 뜻이 흐려져, 오히려 읽는 분의 시간을 더 쓰게 만든다.

# 후속 대기 — 유튜브 캐러셀 재설계

> **상태: 사양 확정 · 착수 대기**(관리자 통계 개편이 끝난 뒤).
> 3R-B 에서 만든 "한 번에 한 장" 트랙이 **의도와 달랐다.**

## 무엇이 어긋났나

지시는 *"각자 영역을 캐러셸로 만들어서 … 대표영상 한 개씩, 즉 3개만 임베디드"* 였고, 나는 이것을 **한 장만 보이는 트랙**으로 구현해 섹션 높이를 987.9 → 724.9px 로 줄였다.

사용자 정정: *"우리 프로젝트 캐러셸처럼 **나머지 항목이 보이는** 캐러셸을 말하는 것이었다. 따라서 **이전 영역의 크기를 되돌려** 확보된 영역 내부에서 카드 캐러셸을 제작한다."*

→ 요구는 **높이 축소가 아니라 형태**였다. 옆 카드가 **보이는** 캐러셀이다.

## 사양

| 항목 | 내용 |
|---|---|
| 영역 크기 | **3R-B 이전으로 되돌린다**(≈988px). 줄이는 것이 목적이 아니다 |
| 형태 | `#showcase` 처럼 **양옆(또는 다음) 카드가 보이는** 캐러셀. 한 장만 꽉 채우지 않는다 |
| 대상 | 세 갈래 각각 — 인게임 정보성 콘텐츠 · 포트폴리오용 영상 · 대표 쇼츠 |
| 트래픽 | **대표 영상을 제외한 항목은 썸네일만 먼저** 불러온다 |

## 판단이 필요한 지점 (구현 시 실측으로 정할 것)

- **3D 캐러셀을 그대로 복제하지 마라.** `#showcase` 의 3D 캐러셀은 순환·자동넘김·배경 에코·필터가 한 덩어리다. 옆 카드가 보이는 효과만 필요하면 **지금의 scroll-snap 트랙에서 카드 폭만 줄여** 다음 카드가 걸치게 하는 쪽이 훨씬 싸다(리뷰 트랙과 같은 부품 유지).
- 3R-B 에서 **두 갈래를 나란히 세우고**(`.ytb-groups` 2열) **카드 폭 상한 300px 을 폐기**(→424px)했다. 높이를 되돌린다면 이 둘도 함께 재검토 대상이다.
- 3R-B 의 **쇼츠 캡션 2줄 클램프**와 `fitShorts` 폭 상한 `[130,220]` 은 높이를 맞추려던 처방이다. 높이가 바뀌면 다시 재야 한다.

## 트래픽 — 이미 확보된 것과 새로 필요한 것

- **iframe 은 지금도 0 개다.** 전부 파사드(썸네일 + 재생 버튼)이고 클릭해야 임베드가 생긴다 — "임베디드 3개만"의 실질은 이미 달성돼 있다.
- 남은 것은 **썸네일 이미지**다. 옆 카드가 보이면 그만큼 썸네일이 더 보인다 → **대표(첫 장) 외에는 지연 로딩**이 유지되는지, 넘길 때 비로소 받는지 실측할 것.
- 합격선: **스크롤 0 에서 유튜브 썸네일 요청이 갈래당 1장(총 3장)을 넘지 않을 것.**
