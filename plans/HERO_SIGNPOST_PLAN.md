# 첫 화면 — 자동 연출 정지 · 나무 표지판 안내 연출 기획서

> **v2 (2026-08-07). v1 구현 완료 후 사용자 조정 지시 반영. 코드는 §6·§7 확정 후 별도 라운드로.**
>
> 사용자 기획의도(원문): **"화면의 강조를 주고 싶은 부분은 오른쪽의 프로젝트 내역이지 내 사진이나 철학이 아니라고 생각한다. 따라서, 사진과 세 문장은 수동으로 클릭해서 보도록 남긴다."**
>
> v2 조정 지시(원문 요약): 표지판 **3배 확대 + 영역 오른쪽으로 튀어나오게**(일부만 걸침) · 페이드인 **3초** · **3초씩 4개 → 페이드아웃 → 7초 뒤 재등장 반복** · **영역 밖에서 페이드인 후 안으로 이동**하는 등장 흐름 · hover 제목 교체에 **잭팟(슬롯) 연출** 검토.

## 0. 이 기획의 한 문장

**첫 화면의 움직임 예산을 왼쪽(사진·문장)에서 걷어 오른쪽(프로젝트 목록)에 몰아준다.**

## 1. 멈추는 것 — ✅ v1 에서 구현 완료 (`ead228a`)

문장 회전·사진 회전 제거(클릭 전환으로), 스크롤 휠 숨김, `hero-rotation-done` 로드 직후 발신(쇼케이스 캐러셀 생존), 첫 화면 사진 확대 제거·이력서 사진 확대 유지. 상세는 v1 이력과 커밋 메시지 참조. **v2 에서 건드리지 않는다.**

## 2. 나무 표지판 — v2 조정

### 2-1. 크기 · 위치 (변경)

- **크기 3배**: 24×16 → **72×48**(데스크톱).
- **패널 오른쪽 밖으로 튀어나온다**: 대부분은 영역 밖, **일부만 영역에 걸친다.** 권장 배치 — 폭 72px 중 **약 22px 만 패널 안**, 50px 은 밖(비율은 구현에서 실측 조정).
- v1 의 "행 끝 `→` 와 7px 이격" 제약은 **해소된다** — 표지판 몸통이 패널 밖으로 나가므로 `→◀` 충돌 자체가 사라진다. 단 걸치는 22px 이 제목 칸을 침범하지 않는지 재야 한다.

**★ 넘침 함정 — 이 변경의 최대 리스크.** 튀어나온 50px 이 뷰포트 오른쪽 끝을 넘으면 **가로 스크롤이 생긴다**(이 저장소의 절대 금지 항목). 패널 오른쪽~뷰포트 사이 여백은 폭마다 다르다.
- 처방: 튀어나오는 양을 `min(50px, 실제 남은 여백 − 4px)` 로 **클램프**. 여백이 부족한 폭(760~1000 구간 의심)에서는 튀어나옴이 자동으로 줄어든다.
- `body{overflow-x:clip}` 으로 가리는 방법은 **금지** — 다른 넘침 버그까지 함께 숨긴다.
- 표지판은 `pointer-events:none` — 페이지 여백 위에 떠 있어도 클릭·hover 를 가로채면 안 된다.

### 2-2. 등장 (변경)

- 첫 화면 갱신 **3초 뒤** 등장(v1: 1.57초).
- **등장 흐름 = 밖에서 페이드인 → 안으로 진입.** 완전히 영역 밖 위치(안착 위치보다 오른쪽 ~28px)에서 `opacity 0→1` 페이드인(~0.8초)한 뒤, **왼쪽으로 미끄러져 안착 위치(첫 대상 줄)에 도착**(~0.6초). 도착이 곧 첫 줄 cue 시작이다.
  - 사용자 근거(원문): "페이드인 할 때 바로 hover하는 것보다 영역 밖에서 페이드인 후, 영역 내부로 이동하는 흐름이 자연스럽다."
- 자리는 처음부터 차지하지 않는다 — `position:absolute` 오버레이라 레이아웃 이동은 원래 0.

### 2-3. 줄 이동 (유지)

가리키는 줄이 바뀌면 `translateY` 로 미끄러진다. 실제 사용자 hover 와 표지판을 공유하고, 사용자 hover 가 항상 우선한다.

## 3. 자동 순회 — v2 타이밍

### 3-1. 대상과 순서 (유지)

직군별: 무릉 → 가마솥 → 여우숲 → 원쁠원 / 엔진별: 역순. 보이는 `pbtn-set` 의 DOM 순서로 고른다.

### 3-2. 타이밍 (변경)

| 단계 | v1 | **v2** |
|---|---|---|
| 등장 | 로드 +1.57초 페이드인 | **로드 +3초, 밖에서 페이드인 → 진입**(§2-2) |
| 줄당 체류 | 1.5초 | **3초** |
| 한 바퀴 | 6초 | **12초** |
| 바퀴 종료 후 | 쉬는 자리(패널 머리줄, op .34)로 이동 → 3초 휴지 | **페이드아웃(~0.6초) → 7초 휴지 → §2-2 등장 연출 재실행 → 반복** |

- **v1 의 '쉬는 자리' 개념은 폐기한다** — 바퀴 사이에 표지판이 아예 사라지므로 중립 지점이 필요 없다.
- 해석 명시: 지시문 "7초 뒤 다시 3초 페이드인 후 반복"을 **페이드아웃 → 7초 휴지 → (초기 등장과 같은) 페이드인+진입 → 순회 재개**로 읽었다. "3초"가 페이드인 소요 시간을 뜻한 것이면 진입 포함 총 ~1.4초를 3초로 늘리면 된다(값만 조정).

### 3-3. 제목만, 배경은 정지 (유지)

`.is-cue` 는 제목 교체 규칙에만 얹혀 있고 배경(`.is-sharp`·에코)에는 없다. v2 에서도 불변.

### 3-4. 멈춤과 재개 (유지)

프로젝트 직접 hover 만 취소 / 취소 후 3초 무반응 시 재개 / 화면 밖 취소·복귀 시 재개 / 그 외 이벤트로는 취소하지 않음 / reduced-motion 은 순회 없음.
- v2 보완: 취소 후 재개할 때는 **등장 연출 없이** 현재 위치에서 페이드인만 한다(밖에서 다시 진입하면 3초짜리 재개 규칙과 어긋나게 길어진다). 등장 연출은 **바퀴 사이 재등장에만** 쓴다.

### 3-5. 모바일·터치 (조정 필요 — §6-2)

순회는 끔(유지). 표지판 크기는 §6-2 에서 확정.

---

## 4. 접근성 (유지)

표지판 `aria-hidden` · 제목 교체는 DOM 텍스트 불변(두 `<b>` 표시 전환) · 문장·사진 키보드 조작.

## 5. 제목 교체 연출 후보 — "잭팟처럼 위아래로 뒤바뀌는 연출이 가능할까?"

**가능하다.** 현재 구조가 유리하다: 두 제목(`.pbtn-t` 기본 / `.pbtn-th` 내부 제목)이 **이미 같은 칸에 겹쳐 존재**하고(hover 시 불투명도 교차), DOM 텍스트를 갈아끼우지 않는다. 슬롯 연출은 이 두 요소에 `translateY` 를 주고 칸(`.pbtn-tt`)에 `overflow:hidden` 클립을 씌우면 성립한다.

| 후보 | 연출 | 장점 | 리스크 |
|---|---|---|---|
| **A. 잭팟 롤 (수직 슬롯)** ★권장 | 기본 제목이 **위로 굴러 나가고** 내부 제목이 **아래에서 굴러 들어온다**(~0.4초, 살짝 오버슈트 후 안착하면 릴이 멈추는 손맛) | 요청 그대로. 현 구조에 정확히 얹힘. "다음 패가 나온다"는 은유가 '궁금증 유발' 의도와 맞음 | ① 좁은 폭에서 제목이 **2줄로 접히면** 굴러 들어오는 높이가 달라 어긋남 — 이동량을 %가 아니라 칸 높이 기준으로 · ② 빠르게 여러 줄을 훑는 실제 hover 에서 롤이 연쇄되면 어지러움 — 짧은 지속시간(0.4초)과 대칭 역재생으로 완화 |
| **B. 팻말 뒤집기 (rotateX 플립)** | 나무 팻말이 **반 바퀴 뒤집히며** 내부 제목이 나타남(공항 스플릿플랩 느낌) | **나무 표지판 세계관과 은유가 일치**(팻말을 뒤집어 보여준다) | 3D 텍스트가 **WebKit 에서 애니메이션 중 흐릿해지는** 고질 · 두 면 관리로 구현이 A 보다 복잡 |
| **C. 크로스페이드 + 슬라이드 8px** | 지금 페이드에 **미세한 상향 슬라이드**만 추가 | 가장 안전·저렴. 실패 모드 없음 | "미흡하다"는 지적에 대한 답으로는 부족할 수 있음 |
| D. 글자 스크램블 (기각) | 글자가 한 자씩 바뀜 | — | **DOM 텍스트를 갈아끼워야 해서 §4 접근성 원칙 위반.** 가변 폭 한글에서 줄렁임. 기각 |

**권장: A.** 요청에 직접 부합하고, 현 구조 위에 클립+이동만 얹으면 되며, 실제 hover 에도 같은 연출이 적용돼 자동/수동이 한 문법이 된다. B 는 은유는 더 좋지만 렌더 리스크가 실재한다(A 채택 후 원하면 B 를 실험 라운드로).
공통 규칙: `prefers-reduced-motion` 에서는 **즉시 교체**(연출 없음). 상태 배지·부제 줄은 연출에 태우지 않는다(행이 가로로 흔들리면 정렬 인상이 무너진다 — v1 확정 유지).
