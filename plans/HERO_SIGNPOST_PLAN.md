# 첫 화면 — 자동 연출 정지 · 나무 표지판 안내 연출 기획서

> **상태: 기획 확정 대기. 코드는 확정 후 별도 라운드로 진행한다.**
>
> 사용자 기획의도(원문): **"화면의 강조를 주고 싶은 부분은 오른쪽의 프로젝트 내역이지 내 사진이나 철학이 아니라고 생각한다. 따라서, 사진과 세 문장은 수동으로 클릭해서 보도록 남긴다."**

---

## 0. 이 기획의 한 문장

**첫 화면의 움직임 예산을 왼쪽(사진·문장)에서 걷어 오른쪽(프로젝트 목록)에 몰아준다.**

지금 첫 화면에서 저절로 움직이는 것은 셋이다 — 문장 회전 · 사진 회전 · 스크롤 휠. 셋 다 **왼쪽이거나 아래를 가리킨다.** 정작 보여주고 싶은 오른쪽 프로젝트 목록은 가만히 있다. 움직임은 시선을 끄는 가장 강한 수단인데, 그 예산을 강조하고 싶지 않은 곳에 쓰고 있었다.

---

## 1. 멈추는 것 — 현재 수치와 처리

실측한 현재 값이다.

| 연출 | 현재 값 | 처리 |
|---|---|---|
| **세 문장 회전** | `HOLD 3400ms` · `FADE 450ms`. s1→s2→s3→s1 로 돌아와 정지 | **자동 재생 제거.** s1 고정, **클릭으로 다음 문장** |
| **사진 회전** | `FIRST 3000ms` · `EVERY 5000ms` · `FADE 600ms` · `DRAG 40px` | **자동 전환 제거.** 첫 장 고정, **클릭으로 다음 사진**(좌우 드래그는 유지) |
| **스크롤 휠 표시** | 처음 표시 → 활동 시 숨김 → `10000ms` 무활동 시 재등장 | **감춘다**(되살리기 쉽게 남긴다 — §6-3) |

### 1-1. ★ 반드시 남겨야 하는 발신 하나

문장 회전이 끝날 때 `revealArrows()` 가 `hero-rotation-done` 이벤트를 쏘고, **맨 아래 쇼케이스 캐러셀이 그것을 받아 자동 넘김을 켠다**(CLAUDE.md §2-21 ②, §2-27 ④). 회전만 지우고 이 발신을 빼면 **캐러셀 자동 넘김이 조용히 죽는다.**
→ 회전을 제거하되 **로드 직후 즉시 `hero-rotation-done` 을 발신**한다. (현재 `heroReady` 가 true 로 시작하도록도 되어 있어 이중 안전이지만, 발신 자체를 없애지는 않는다.)

### 1-2. 클릭 전환의 규칙

- **문장**: 문장 블록 클릭 → 다음 문장(3개 순환). 페이드는 기존 `FADE 450ms` 재사용.
- **사진**: 클릭 → 다음 사진(2장 순환). 드래그(문턱 40px)는 좌우 방향 유지. 페이드 `600ms` 재사용.
- **★ 첫 화면 사진의 "클릭 확대"는 없어진다**(사용자 지시로 규칙 변경). 방지턱 아래 **이력서 사진(`.rz-photo`)의 확대는 그대로 유지**한다 — 지시가 첫 화면만 지목했고, 확대 경로를 전부 없애면 사진을 크게 볼 방법이 사라진다.
- 드래그와 클릭이 싸우지 않게 기존 40px 문턱을 그대로 쓴다(이동 40px 미만 = 클릭).

## 2. 나무 표지판 — 새 안내 장치

### 2-1. 정체
**오른쪽 프로젝트 패널의 오른쪽 끝자락**에 붙는, 왼쪽을 가리키는 **화살표 모양 나무 표지판**. 색은 **빨강**(§6-1 — 사용자가 "우선 빨강, 별로면 주황으로 재수정" 지시).

**이것은 장식이 아니라 hover 표시다.** 사용자가 프로젝트에 마우스를 올리면 표지판이 그 줄을 가리킨다. 자동 연출은 그 표시를 빌려 쓰는 것뿐이다.

### 2-2. 등장
첫 화면이 갱신되고 **1초 뒤 페이드인**. 등장 시 레이아웃이 밀리지 않도록 자리는 처음부터 차지하고 `opacity` 만 올린다(§2-27 의 화살표 선례와 같은 처리).

### 2-3. 움직임
- 가리키는 줄이 바뀌면 **세로로 미끄러진다**(`transform: translateY`). 줄 높이가 단일값이라 이동량 계산이 안정적이다(§2-28 ②).
- 실제 사용자 hover 와 자동 연출이 **같은 표지판을 공유**한다. 사용자 hover 가 항상 우선한다.

## 3. 자동 순회 연출

### 3-1. 대상과 순서
**화면에 보이는 위→아래 순서**를 따른다(사용자 확정). 토글 상태에 따라 순서가 바뀐다.

| 토글 | 순회 순서 |
|---|---|
| **직군별**(기본) | 무릉 천정원 지하 → 가마솥 SIGMA → 여우숲 → 원쁠원 |
| **엔진별** | 원쁠원 → 여우숲 → 가마솥 SIGMA → 무릉 천정원 지하 |

대상 4개는 **고정**(언리얼 맵 제작·헤스티·니달리는 순회에서 제외). 구현은 "보이는 `pbtn-set` 안에서, 대상 4개에 해당하는 것을 DOM 순서대로" 고른다 — 위치를 손으로 적지 않는다(§2-27 ⓒ 의 교훈: 위치 기반 자동 부여는 왜곡을 낳지만, **여기서는 순서가 곧 화면 순서**라 DOM 순서가 정답이다).

### 3-2. 타이밍
- 한 줄당 **1.5초**, 4줄 = **6초**
- 한 바퀴가 끝나면 표지판이 **쉬는 자리로 돌아가고**, 3초 뒤 다시 시작(§6-2 에서 확정)

### 3-3. 무엇이 바뀌나 — 제목만, 배경은 정지
프로젝트에 hover 하면 지금은 **① 제목이 내부 제목으로 바뀌고 ② 배경이 그 프로젝트 썸네일로 선명해진다.** 자동 연출은 **①만** 한다(사용자 확정).

> 이 연출의 목적은 "일부러 궁금증을 자아내려고 내부 제목을 보여주는 것"이므로 제목 교체가 본체이고, 배경까지 6초마다 갈아치우면 첫 화면 전체가 계속 출렁인다.

**★ 구현상 주의**: `:hover` 는 JS 로 만들 수 없다. 별도 클래스(예: `.is-cue`)를 붙이고, **기존 hover 규칙 중 제목 교체 부분에만** 그 클래스를 선택자로 추가한다. **배경(`.is-sharp`·썸네일 교체) 규칙에는 추가하지 않는다.** 이 분리가 이번 구현의 핵심 작업이다.
계측할 때 클래스로 재타깃하면 **특정도가 달라져 결과가 어긋난다**(§2-28 ⑩) — 실제 hover 는 `computer{action:"hover"}` 로 따로 확인한다.

### 3-4. 멈춤과 재개
| 사건 | 동작 |
|---|---|
| 사용자가 **프로젝트에 직접 hover** | 즉시 취소. 표지판은 사용자가 가리킨 줄로 |
| 취소 후 **3초간 반응 없음** | 다시 시작 |
| **첫 화면이 화면 밖으로** | 취소(IntersectionObserver). 되돌아오면 재개 |
| 그 외(마우스 이동·스크롤 등) | **취소하지 않는다** — 사용자 지시대로 프로젝트 hover 만이 취소 조건이다 |
| `prefers-reduced-motion` | 자동 순회 없음. 표지판은 첫 항목을 가리킨 채 고정 |

### 3-5. 모바일·터치
**표지판만 보이고 순회는 끈다**(사용자 확정). 현재 hover 연출은 `min-width:760px and (hover:hover)` 안에서만 켜지므로, 그 밖에서는 표지판이 **첫 항목을 가리킨 채 고정**된다.

## 4. 접근성

- 표지판은 **순수 장식**이므로 `aria-hidden="true"`. 자동 연출이 스크린리더에 "제목이 계속 바뀐다"고 읽히면 안 된다.
- 제목 교체는 시각 효과이므로 **DOM 텍스트를 갈아끼우지 않고** 기존 hover 와 같은 방식(두 `<b>` 의 표시 전환)을 그대로 쓴다. 접근성 트리의 이름은 불변.
- 클릭 전환이 붙는 문장·사진은 **키보드로도 조작 가능**해야 한다(`button` 또는 `tabindex`+Enter/Space). 지금 사진은 Enter 로 라이트박스가 열렸으므로, 그 자리를 "다음 사진"이 대신한다.

## 5. 검증 계획 (구현 라운드용)

1. 자동 움직임 0 — 15초 관찰: 문장·사진 불변, 스크롤 표시 없음
2. `hero-rotation-done` 발신 확인 + **쇼케이스 캐러셀 자동 넘김 생존**
3. 클릭 전환: 문장 3순환 · 사진 2순환 · 드래그 40px 문턱 유지 · 키보드 조작
4. 이력서 사진(`.rz-photo`) 확대 **유지** 확인
5. 표지판: 1초 뒤 페이드인 · 레이아웃 이동 0 · 실제 hover 추종(`computer{action:"hover"}`)
6. 순회: 1.5초 간격 · 4개 순서(직군별/엔진별 각각) · **배경 불변** · 6초 후 휴지 · 3초 뒤 재시작
7. 취소 규칙: 프로젝트 hover 시 취소 · 3초 뒤 재개 · 화면 밖 취소 · 그 외 이벤트로는 취소 안 됨
8. reduced-motion 정지 · 375px 순회 꺼짐·표지판 고정 · 760/1000/1280 가로 스크롤 0 · 콘솔 0

## 6. 확정 필요 (구현 전 — 권장안 포함)

| # | 질문 | 권장 |
|---|---|---|
| 1 | 표지판 색 | **빨강으로 먼저 구현.** 사용자가 "별로면 주황으로 재수정 요청"이라 했으므로, 색을 CSS 변수 한 곳(`--signpost`)에 두어 **한 줄로 갈아끼울 수 있게** 만든다 |
| 2 | 한 바퀴(6초) 후 재시작 간격 | **3초** — 취소 후 재개 간격과 같은 값. 규칙이 하나라 예측 가능하다 |
| 3 | 스크롤 휠 표시를 지울까, 숨길까 | **숨긴다**(CSS 한 줄 + 주석). "당장은 감춰라"는 되살릴 여지를 남기라는 뜻으로 읽었다 |
| 4 | 문장·사진이 클릭 가능하다는 표시 | **커서만 바꾼다**(`cursor:pointer`). 눈에 띄는 힌트를 붙이면 "왼쪽을 강조하지 않는다"는 이번 기획의도와 정면으로 충돌한다 |
