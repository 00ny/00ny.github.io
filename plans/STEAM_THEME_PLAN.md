## 1. 평가 — 강점 4, 저항 4 (전부 해소 가능)

### 강점
1. **후킹이 확실하다.** 게임 실무자는 Steam 라이브러리 UI를 매일 본다. 첫 화면이 그 문법이면 설명 없이 "게임 UX로 사고하는 사람"이 전달된다. A안(일반 카드 그리드)보다 정체성이 강하다.
2. **은유가 정확하다.** 포트폴리오 = 게임 라이브러리. 좌측 목록 → 상세 페이지 구조가 우리 "선택창 → 문서" 흐름과 1:1이다.
3. **상세 페이지 매핑이 공짜로 맛있다.** Steam 게임 페이지의 칸이 우리 데이터와 정확히 대응된다 — §3-4 표 참조. 라이브 지표·업데이트 노트·역할 경계가 전부 제자리를 찾는다.
4. **hyun x claude 로고 = 정직 고지의 브랜드화.** "배현이 기획, Claude가 재구성"이라는 사이트 전체의 정직성 문법이 입장 연출과 로고로 승격된다.

### 저항과 해소
1. **트레이드 드레스(외형 모방).** "동일하게"를 문자 그대로 하면 Valve 상표·에셋 복제가 된다.
   → **원칙: 레이아웃 문법만 가져오고 전 요소 재제작.** Valve 로고·아이콘·CSS·이미지 반입 금지, 전용 폰트(Motiva Sans) 대신 Pretendard. 푸터에 한 줄 오마주 고지("Steam 스타일 오마주 — Valve와 무관") 권장. 취업 포트폴리오 맥락의 오마주는 업계에서 통용되는 장르다.
2. **채용 담당자의 15초.** Steam UI는 밀도가 높다 — 처음 온 사람이 "누구인지"를 놓칠 수 있다.
   → 상단 계정명 '배현' + 좌측 목록 최상단 고정 항목 「프로필 · 이력서」 + 라이브러리 홈 첫 줄을 대표작 강조로.
3. **입장 연출은 재방문자에게 짐이다.**
   → 세션당 1회(sessionStorage) · 클릭/키 즉시 스킵 · **총 2초 이내** · `prefers-reduced-motion`이면 생략 · 연출 중에도 뒤 화면 프리로드.
4. **방명록은 정적 사이트라 서버가 없다.** "입력자는 못 보고 관리자만"은 저장소가 필요하다. 관리자 백엔드는 localhost라 공개 방문자가 닿지 못한다.
   → 외부 수신함으로 해결. 후보 2안(§3-6): **A. Google Forms 숨은 POST**(가입 불요·스프레드시트 수신·무제한) / **B. Formspree**(메일 수신·월 50건). 목업 단계에서는 모달 UI만 만들고 수신처는 이식 때 연결.

**결론: 저항 전부 해소 가능. 진행할 가치가 있다.** A안의 카드 그리드·hover 연출·라이브 칩은 라이브러리 '모든 게임' 구획에 그대로 재활용된다 — A안은 버려지는 게 아니라 부품이 된다.

## 3. Steam 프레임 설계 (②)

### 3-1. 최상단 바
`[◈ hyun x claude]  내 웹사이트 목차들 ▾` ──── 우측 `[🔊][🔔][?][배현 ▾][🖥][─][□][×]`
- **내 웹사이트 목차들** 드롭다운 = 기존 목차 승계: 이력서 · 분석·리뷰 · 유튜브 · 추가 링크 · GitHub 히스토리.
- 우상단: `?` = **방명록 모달**(§3-6). `🔔` = 업데이트 노트(최근 push·프로젝트 소식 — analytics.js의 lastUpdate 재사용). 나머지(🔊·🖥·창 버튼)는 장식 no-op(× 는 이스터에그 여지).
- 계정 `배현 ▾` 드롭다운: 이력서로 이동 · 메일 복사 · 노션.

### 3-2. 내비 바
`←  →   라이브러리   배현` — 상점·커뮤니티 제거(보류). ←→는 실제 history. '배현' = 프로필(이력서 섹션).

### 3-3. 좌측 사이드바 (목록창)
- 검색창(제목 실시간 필터) + 필터 버튼 → **라이브러리 필터 패널**(Steam 문법 복제): 분류(제작 4 / 역기획서 2 / 제안서 2) · 엔진(MSW/Unity/Unreal/Figma) · 상태(LIVE/종료).
- `— 즐겨찾기 (2)`: 원쁠원 · 누크발(라이브 2종). `— 제작 (4)` `— 역기획서 (2)` `— 제안서 (2)`: 프로젝트 제목.
- 최상단 고정 `프로필 · 이력서`.

### 3-4. 메인 — 라이브러리 홈과 상세
**홈**: ① `새로운 업데이트` 줄 = 프로젝트 소식 카드(누크발 NEW·라이브 지표 등 실데이터) ② `최근 작업` 줄 = 시기순 대형 카드 ③ `모든 프로젝트 (8)` = **A안 카드 그리드 재활용**(hover 연출 포함).

**상세**(좌측 목록 클릭 시, Steam 게임 페이지 문법):

| Steam | 우리 것 |
|---|---|
| 히어로 배너 + 로고 | 프로젝트 에코/키아트 + 제목 |
| 파란 `설치` 버튼 | **`문서 열기 →`** (실제 프로젝트 페이지로) |
| 필요한 공간 25.69GB | 원본 분량 (47p 등) |
| 마지막 플레이 | 최종 업데이트 (2026.08) |
| 플레이 시간 264.8시간 | **라이브 지표** (34명 · 85% / 6명 · 54분) |
| 특집/뉴스 피드 | 업데이트 노트 · 제작 여정 |
| 우측 `노트` | 킬러 카드 훅(역할 경계·카뮤 대조 ↓) |
| `내 평가` | 스스로 남긴 한계·경계 표기 |

상세는 **프레임 안 요약 랜딩**이고, 본문은 기존 `projects/*.html`로 보낸다 — 스캔 구조 작업이 그대로 산다.

### 3-5. 모바일(1/9)
사이드바 숨김 + 홈 1열. 깨지지만 않으면 된다.

### 3-6. 방명록 ('?')
- Steam 스타일 모달: 닉네임(선택) + 메시지 + `남기기`. 제출 후 "감사합니다" 토스트. **화면 어디에도 목록을 보여주지 않는다.**
- 수신: **A안 Google Forms 숨은 POST**(가입 불요, 응답은 관리자 스프레드시트 — "나만 본다" 충족) 권장 / B안 Formspree(메일 수신). 이식 라운드에서 사용자 계정으로 1회 연결.

## 6-B. 확정 RULE (2026-08-28 — 이후 모든 작업의 상위 규칙)

> **RULE 0 (최상위) — Steam 클론.** 화면 색·글씨체·간격·정렬을 Steam 라이브러리와 **100% 동일하게** 맞추는 것을 목표로 삼는다. 단 로고·상표·유료 폰트 파일(Motiva Sans) 등 **자산 자체는 반입 금지** — 색상값·레이아웃·타이포 스케일은 자유롭게 일치시키고, 폰트는 가장 근접한 무료 대체를 쓴다.
> **RULE 1 — 한 줄.** 전체화면(1920)에서 **줄바뀜이 생기는 모든 영역은 한 줄로 만든다.** 방법은 문구 축약(정보 최소화)이지 폰트 축소가 아니다.
> **RULE 2 — 통일성.** 같은 분류(제작/역기획서/제안서/리뷰)의 카드는 **같은 필드 구성·같은 순서·같은 색 규약**을 갖는다. 분류마다 다른 색을 쓰되 분류 안에서는 예외 없이 통일한다.
> **RULE 3 — 글씨체 단일.** 사이트 전체가 하나의 폰트 패밀리로 간다(수치·라벨용 mono 1종만 예외 허용).
