# 상단 목차 바 — 유리(글라스) 설계서

> 작성 2026-07-31. 기준 커밋 `f0f7c86`. **설계 문서다 — 이 문서의 CSS는 아직 어느 파일에도 적용하지 않았다.**
> 사용자 지시: *"지금처럼 단색으로 두지 말고, 이전처럼 배경의 색이 영역에 들어오게 한다.
> 단지 내용물들이 영역과 겹칠 때 물 속에서처럼 번지게 하라. 즉, 정보를 배경으로써 활용되도록 상단바를 설정하란 얘기다."*
> 선행: CLAUDE.md §2-10(목차 바 = 투명 오버레이 + `.is-scrolled`), §2-27(콕핏 히어로), §2-28 ④(blur 는 가우시안 σ, 합성은 √(a²+b²)).

## 0. 무엇이 문제였고, 무엇을 기각했나

### 0-1. 실측한 현상 (1280×800, 이 문서 작성 중 계측)

| 항목 | 값 |
|---|---|
| `.hx`(콕핏 히어로) 높이 | **852px** — 뷰포트(800)보다 52px 높다. **첫 화면을 끝까지 보려면 반드시 스크롤해야 한다.** |
| 회전 문장(`#heroLead`) 상자 | top 70 / bottom 104.8 (높이 34.8) |
| 목차 바 | top 0 / bottom 56 (`position:fixed`, z-index 50) |
| **scrollY = 0 에서의 겹침** | **0** (문장 위 여백 14px) |
| **겹침이 생기는 구간** | **scrollY 14 → 104.8** |
| 문장이 바 안에 통째로 들어가는 구간 | scrollY **48.8 → 70** (겹침 34.8px = 100%) |
| 그때 바의 배경 | **투명** — `.is-scrolled` 는 scrollY > 772 에서야 켜진다 |

→ 사용자가 본 "첫화면에서 완전히 겹친다"는 **scrollY 14~105 구간**의 화면이다.
scroll 0 자체는 겹치지 않는다. 즉 문제는 여백이 아니라 **"바가 자기 영역을 갖지 않은 채 콘텐츠가 그 밑을 통과한다"** 는 것이다.

### 0-2. 기각한 안

- **ⓐ 단색 분리(바에 상시 불투명 배경)** — 시도했고 겹침은 완전히 사라졌으나(스크린샷 확인) 사용자가 **"이전 디자인보다 보기 좋지 않다"** 로 기각. 코드는 전량 되돌렸다.
- **ⓑ 히어로를 바 높이만큼 아래로** — **불가**. 겹침은 scroll 0 이 아니라 스크롤 중에 생기므로 여백을 늘려도 사라지지 않는다. 게다가 세로 예산이 없다(1280×800 에서 요약 카드 바닥이 이미 **797.5px**, 여유 2.5px).
- **ⓒ 히어로 위에서만 문장을 숨김/이동** — 원래 없던 동작을 만들고, 회전 문장·자동 넘김 JS(§2-27 ④ `hero-rotation-done`)와 얽힌다.

### 0-3. 채택 방향 — 겹침을 없애지 않고 **연출로 바꾼다**

바는 거의 투명해서 **히어로의 앰버 방사와 배경색이 바 안으로 들어온다**.
바 밑을 지나는 회전 문장은 `backdrop-filter` 로 **물속처럼 번져** 형태를 잃고 **색과 빛만 남는다**.
바의 글자(사이트명·목차 링크)는 그 위에 또렷하게 얹힌다. → *"정보를 배경으로써 활용"*.

## 1. 물리 — blur 값이 이 설계의 전부다

`backdrop-filter: blur(N)` 의 N 은 **가우시안 표준편차 σ** 다(§2-28 ④).
가우시안은 주기 T 의 무늬를 **exp(−2π²σ²/T²)** 배로 줄인다. 이 저장소가 다루는 무늬는 두 가지다.

| σ | **글자 리듬**(T≈24px, 글자 한 칸) 잔존 | **문장 띠**(T≈70px, 34.8px 줄의 상하 주기) 잔존 | 읽히는 모습 |
|---|---|---|---|
| 6px  | **29.1%** | 86.5% | 글자 윤곽이 그대로 보인다 — "겹쳤다"로 읽힌다. **불가** |
| 8px  | 11.2% | 77.3% | 글자 형태가 희미하게 남는다 — 유리 너머 글씨. 애매 |
| 10px | 3.3% | 66.8% | 형태 거의 소멸. 현재 `.is-scrolled` 가 쓰는 값 |
| **12px** | **0.7%** | **56.0%** | **형태 완전 소멸 + 지나가는 빛 띠는 또렷. 권장** |
| 16px | 0.02% | 35.7% | 띠까지 죽어 "무언가 지나간다"가 잘 안 보인다 — 연출 약화 |
| 20px | ~0 | 19.9% | 사실상 단색. 채택 의미 없음 |

**핵심**: σ 는 *글자 리듬은 죽이고 문장 띠는 살리는* 구간에 있어야 한다.
그 구간이 **10~13px**이고, 두 조건의 균형점이 **12px**이다.

> ⚠️ **blur 는 밝기를 지우지 않는다. 재분배할 뿐이다.**
> 문장이 지나는 띠 안의 평균 밝기는 blur 를 아무리 키워도 그대로 남는다.
> 그래서 **가독성을 실제로 지키는 것은 blur 가 아니라 틴트(tint)** 다. → §2

## 2. 대비 예산 — 최악의 순간 기준으로 재라

### 2-1. 최악의 순간과 그때의 배경 밝기 (실측 + 모델)

최악은 **가장 긴 3번 문장이 바 안에 통째로 들어간 순간**(scrollY 48.8~70).
그 순간 바 뒤에 깔리는 것은 흰 700 24px Hahmlet 글자다.

- **잉크 커버리지 측정값 = 0.2757** — 같은 폰트(`700 24px Hahmlet`)로 3번 문장을 캔버스에 그려 줄 상자(1.45em) 안 평균 알파를 잰 값이다. **이 측정은 재현 가능하다(§7-3에 코드)**.
- 문장 색 `rgba(255,255,255,.90)`, 강조 `<em>` `#F5A45C`, `text-shadow:none`.
- 바 띠 위치의 히어로 배경 ≈ `rgb(36,27,23)` (`--bg` #0E0F13 + `.hx::before` 앰버 방사 α≈.10).

→ blur 후 띠 안 평균 = 0.2757×(233,232,232) + 0.7243×(36,27,23) ≈ **(90,84,81)**.
σ=12 에서 띠 자체의 변조가 56% 남으므로 **설계 기준값은 여유를 둬 `(105,98,95)`** 로 잡는다.

### 2-2. 틴트 농도별 대비 (바 글자 vs 번진 배경, WCAG 2.x)

바 글자는 두 종류다. **앰버 브랜드(`배현 ·` = `--accent-strong` #F5A45C)가 흰 링크보다 먼저 무너진다.**

| 틴트 `rgba(14,15,19,α)` | 목차 링크 `rgba(255,255,255,.60)` | 브랜드 앰버 `#F5A45C` | 판정 |
|---|---|---|---|
| α = .20 | 4.00 | **3.82** | ✗ 둘 다 미달 |
| α = .25 | 4.19 | 4.06 | ✗ |
| α = .30 | 4.40 | 4.31 | ✗ (아깝다) |
| **α = .35** | **4.61** | **4.66** | ✓ 통과, 여유 얇음 |
| **α = .40** | **4.84** | **4.92** | ✓ **권장** |
| α = .45 | 5.06 | 5.15 | ✓ 여유 있으나 유리가 탁해진다 |

### 2-3. 유리를 더 맑게 하고 싶다면 — 글자를 밝혀라

α 를 낮추는 대신 바 글자를 올리면 같은 AA 를 얻는다.

| 조합 | 링크 대비 | 브랜드 대비 | 대가 |
|---|---|---|---|
| α=.20 + 링크 `rgba(255,255,255,.82)` + 브랜드 **흰색** `--ink` | 5.87 | 6.67 | **앰버 브랜드 글자를 포기해야 한다** |
| α=.25 + 링크 `.82` + 브랜드 흰색 | 6.27 | 7.0 급 | 위와 같음 |

→ **선택지는 둘 중 하나다. "맑은 유리 + 흰 글자" 또는 "약간 탁한 유리 + 앰버 브랜드 유지".**
현재 바의 앰버 브랜드는 §2-10 액센트 절제 체계 안에서 정한 색이므로, **기본 권고는 후자(α=.40)** 다.

> `text-shadow` 는 **보조 수단으로만** 쓴다. WCAG 는 그림자를 대비로 인정하지 않는다 —
> 위 표를 통과시키는 용도로 쓰면 안 되고, 통과한 뒤 가장자리를 또렷하게 만드는 용도로만 쓴다.

## 3. 권장 레시피 (CSS 초안 — 아직 적용하지 않았다)

### 3-1. A안 · 최소 변경 (권장, `.toc-bar` 블록만 교체)

```css
/* ★ 유리 상단 바 — 배경을 지우지 않고 **번지게** 한다.
     · blur 12px : 글자 리듬(T≈24px) 잔존 0.7% → 형태 소멸 / 문장 띠(T≈70px) 잔존 56% → 지나가는 빛은 보인다
     · saturate  : 틴트가 앰버 방사의 채도를 깎으므로 되살린다("배경의 색이 영역에 들어오게")
     · 틴트 .40  : 최악의 순간(긴 문장이 바 안에 통째로 들어올 때) 링크 4.84:1 · 앰버 브랜드 4.92:1 (AA)
       ⚠ 틴트를 낮추려면 바 글자를 밝혀야 한다 — 앰버 브랜드가 흰 링크보다 먼저 무너진다(설계서 §2-3).
     · backdrop-filter 는 두 상태가 **같은 값**이라 transition 대상에서 뺐다(필터 애니메이션은 매 프레임 재블러다). */
.toc-bar{
  position:fixed; top:0; left:0; right:0; z-index:50;
  height:56px;
  background:rgba(14,15,19,.40);
  -webkit-backdrop-filter:blur(12px) saturate(140%);   /* Safari 는 접두사 필수 */
          backdrop-filter:blur(12px) saturate(140%);
  border-bottom:1px solid rgba(255,255,255,.05);
  transition:background-color .3s ease, border-color .3s ease;
}
/* 히어로를 벗어나면 틴트만 진해진다 (JS가 토글) — 유리 자체는 같은 값이라 전환에 튐이 없다 */
.toc-bar.is-scrolled{
  background:rgba(14,15,19,.82);
  border-bottom-color:var(--border);
}
@supports not ((backdrop-filter:blur(1px)) or (-webkit-backdrop-filter:blur(1px))){
  /* 유리를 못 만드는 브라우저에서는 번짐도 없다 → 겹침이 그대로 보이므로 틴트로 가린다 */
  .toc-bar{background:rgba(14,15,19,.86)}
}
```

### 3-2. B안 · 끝단 깃털(feather) — 하드 컷을 없애고 싶을 때

A안은 y=56 에서 번짐이 **딱 잘린다**. 그 선이 거슬리면 유리를 의사 요소로 내리고 마스크로 흐린다.

```css
.toc-bar{position:fixed; top:0; left:0; right:0; z-index:50; height:56px; background:transparent; border:0}
.toc-bar::before{                    /* 유리판 — 마스크는 이 판에만 건다(바 글자는 안 흐려진다) */
  content:""; position:absolute; inset:0;
  background:rgba(14,15,19,.40);
  -webkit-backdrop-filter:blur(12px) saturate(140%);
          backdrop-filter:blur(12px) saturate(140%);
  -webkit-mask-image:linear-gradient(to bottom,#000 calc(100% - 10px),transparent);
          mask-image:linear-gradient(to bottom,#000 calc(100% - 10px),transparent);
}
.toc-bar__in{position:relative; z-index:1}   /* 글자를 유리판 위로 */
.toc-bar.is-scrolled::before{background:rgba(14,15,19,.82)}
```

⚠️ **B안은 대비 예산이 달라진다** — 마지막 10px 에서 틴트가 0 으로 사라지므로, 목차 글자가 그 구간에 걸치면 안 된다.
실측: 링크 상자 bottom **44.5**, 브랜드 bottom **39.5** → 깃털 시작선(46px)보다 위. **여유 1.5px 뿐이다.**
깃털 폭을 10px 보다 키우려면 바 높이(56px)를 함께 키우거나 A안으로 가라. **B안은 A안이 마음에 든 뒤에만 시도할 것.**

### 3-3. σ 후보 정리

- **12px — 권장.** §1 표의 두 조건을 동시에 만족하는 유일 구간의 중앙값.
- **10px — 보수적 대안.** 현재 `.is-scrolled` 와 같은 값이라 "아래쪽과 완전히 같은 유리"가 된다. 글자 리듬 잔존 3.3%(허용), 띠 잔존 66.8%로 연출이 조금 더 셈. 두 상태의 필터를 통일하고 싶다면 이쪽.
- **8px — 비권장.** 글자 리듬 11.2% 잔존. "번졌다"보다 "비친다"로 읽혀 사용자 지시에서 멀어진다.

## 4. `.is-scrolled` 와의 관계 — **틴트만 바꾸고 유리는 통일한다**

- 아래쪽(스크롤 후) 분리는 **사용자가 만족한 상태**다. 그 값(`rgba(14,15,19,.82)` + blur 10)을 건드릴 이유가 없다.
- 다만 **blur 값은 두 상태를 같게** 만든다(둘 다 12px, 또는 둘 다 10px).
  이유: 지금 `transition` 목록에 `backdrop-filter` 가 들어 있어 **none → blur(10) 을 0.3초 동안 애니메이션**한다. 필터 애니메이션은 매 프레임 전체 재블러라 임계점에서 프레임이 튈 수 있다. 값이 같아지면 애니메이션 대상이 `background-color`·`border-color` 뿐이라 전환이 공짜가 된다.
- 임계점은 그대로 둔다(`scrollY > 히어로높이 − 80` ≈ 772). 그 지점은 히어로가 거의 다 빠져나간 뒤라 눈에 안 띈다.
- **JS 는 손대지 않는다.** `index.html` 의 토글 IIFE 는 현행 유지.

## 5. 브라우저·구현 함정

1. **Safari 접두사** — `-webkit-backdrop-filter` 를 반드시 병기. 표준형만 쓰면 사파리에서 번짐이 통째로 없어져 §0-1 의 겹침이 그대로 노출된다.
2. **`@supports` 조건은 `or` 로 두 형태를 다 물어라.** `@supports not (backdrop-filter:...)` 만 쓰면 사파리가 폴백으로 떨어진다.
3. **조상에 `filter` 를 걸지 마라.** `filter`(backdrop 아님)를 가진 조상이 생기면 `position:fixed` 자손이 **absolute 처럼 동작**해 바가 스크롤과 함께 흘러간다. 지금은 `body.home` 이 깨끗하다 — 유지할 것.
4. **`backdrop-filter` 는 스태킹 컨텍스트를 만든다.** 바는 이미 z-index 50 이라 영향 없으나, B안의 `::before` 는 `.toc-bar__in` 에 `position:relative; z-index:1` 이 없으면 글자를 덮는다.
5. **`will-change:backdrop-filter` 를 넣지 마라.** 이미 합성 레이어로 승격돼 있고, 메모리만 더 쓴다.
6. **`.toc-bar__links` 의 마스크(560px 이하)와 B안의 마스크는 다른 요소다** — 겹쳐 쓰면 둘 다 유효하지만, 링크 줄 오른쪽 페이드(§style.css 320행)를 지우지 않도록 주의.
7. **프로젝트 페이지 6개는 무관.** 그쪽은 `.site-bar`(static, 38px, `#20252E`)를 쓴다. `.toc-bar` 는 `index.html` 전용임을 grep 으로 확인했다.
8. **ADMIN 마커 19쌍과 무관.** 바 마크업(`index.html` 17~37행)은 마커 밖이다.

## 6. 성능·상호작용

- **비용의 실체**: `position:fixed` + `backdrop-filter` 는 스크롤할 때마다 바 뒤 **1280×56 영역**만 다시 블러한다. 전체 화면이 아니다. 바 높이를 키우지 않는 한 부담은 작다.
- **동시에 도는 애니메이션**: 히어로 회전 문장(0.45s 페이드), 캐러셀 자동 넘김(0.85s transform, 4.5s 간격). 셋 다 합성 레이어에서 돌고 블러 영역과 곱해지지 않는다. **단, 블러 값 자체를 transition 하면 곱해진다 → §4 대로 값 통일.**
- **앵커 착지 여백은 CSS 로만 결정된다**(`.home section{scroll-margin-top:68px}`). 바가 계속 `fixed` 56px 이므로 **현행 12px 여백이 그대로 유지**된다(실측: `#resume` 68.0 / `#reverse` 68.1 / `#unreal` 67.9 / `#links` 68.0). 이 설계는 여백 계산에 아무 영향이 없다.
- **`prefers-reduced-motion`**: 블러는 모션이 아니므로 끄지 않는다. 건드릴 것 없음.

## 7. 검증 계획

### 7-1. 겹침이 아니라 **번짐**을 재는 것이므로, 판정 기준이 다르다
"겹침 0" 은 이제 **목표가 아니다.** 대신 세 가지를 본다.

### 7-2. 최악의 순간을 정확히 잡는 법
문장이 바 안에 통째로 들어오는 스크롤 좌표를 계산해서 그 지점에서 잰다.

```js
// 1280px 기준: leadTop(0) = 70, 높이 34.8, 바 = [0,56]
// 통째로 들어오는 구간 = scrollY 48.8 ~ 70  → 중앙 59 를 쓴다
const lead = document.getElementById('heroLead');
const t0 = lead.getBoundingClientRect().top + scrollY;     // 문서 좌표
scrollTo(0, t0 - (56 - lead.offsetHeight)/2);              // 문장을 바 세로 중앙에
```
폭마다 `.hx` 의 padding-top 이 다르므로(**≥1080: 70 / 760–1079: 92 / <760: 74**) 좌표는 반드시 계산으로 구할 것.

### 7-3. 잉크 커버리지 재측정 (문장을 바꾸면 다시 재라)
```js
const cs = getComputedStyle(document.getElementById('heroLead'));
const c = document.createElement('canvas'); c.width = 1200; c.height = 60;
const x = c.getContext('2d');
x.font = `${cs.fontWeight} ${cs.fontSize} ${cs.fontFamily}`;
x.textBaseline = 'middle'; x.fillStyle = '#fff';
const txt = "…가장 긴 문장…"; x.fillText(txt, 0, 30);
const px = parseFloat(cs.fontSize);
const d = x.getImageData(0, 30 - Math.round(px*0.72), Math.ceil(x.measureText(txt).width), Math.round(px*1.45)).data;
let s = 0, n = 0; for (let i = 3; i < d.length; i += 4) { s += d[i]; n++; }
s/n/255   // ← 커버리지. 현재 3번 문장 = 0.2757
```
커버리지가 올라가면(문장이 더 굵거나 촘촘해지면) **§2-2 표의 대비가 전부 내려간다.** 문안을 바꿀 때마다 재라.

### 7-4. 체크리스트

| # | 항목 | 방법 | 통과 기준 |
|---|---|---|---|
| 1 | 최악의 순간 대비 | §7-2 좌표에서 스크린샷 + §2 모델 재계산 | 링크·**앰버 브랜드** 둘 다 ≥ 4.5:1 |
| 2 | 3문장 각각 | `heroLead.innerHTML` 을 SENTS 3개로 강제 후 1 반복 | 셋 다 통과 (**가장 긴 3번이 최악**) |
| 3 | 폭 5종 | 375 · 760 · 899 · 1000 · 1280 | 가로 스크롤 0, 바 높이 56 유지, 링크 줄 페이드 정상 |
| 4 | 번짐이 실제로 보이는가 | 최악 좌표에서 스크린샷 **육안** | 글자 형태 식별 불가 + 빛 띠는 보임 |
| 5 | 배경색이 바 안으로 들어오는가 | scrollY 0 스크린샷 육안 | 좌상단 앰버 방사가 바 안에서 이어짐 |
| 6 | `.is-scrolled` 전환 | scrollY 760→790 왕복 | 이중 배경·튐 없음, 필터 애니메이션 없음 |
| 7 | 앵커 착지 | `#resume`·`#reverse`·`#unreal`·`#links` `scrollIntoView()` | top ≈ 68 (바 아래 12px) |
| 8 | 회전·자동 넘김 | `#heroWrap` 에 `is-ready` 확인 + #showcase 에서 카드 순환 | 무손상 |
| 9 | 폴백 | DevTools 로 `backdrop-filter` 무력화 | 글자 겹침이 틴트에 가려짐 |
| 10 | 프로젝트 페이지 | `foxforest.html` 의 `.site-bar` | static / 38px / `#20252E` 그대로 |
| 11 | 콘솔 | index + 프로젝트 1개 | 에러 0 |

> 계측 함정(§2-28 ⑩ 재확인): **스타일시트를 고친 뒤 같은 오리진으로 다시 열면 브라우저가 옛 CSS 를 캐시한다.**
> `preview_stop`→`preview_start` 만으로는 안 풀린다. 이번 세션은 **포트를 바꿔 새 오리진으로 여는 방법**으로 우회했다.

## 9. 남은 판단 (구현 전에 사용자 확인 권장)

1. **틴트 α = .40 vs "맑은 유리 + 흰 브랜드"** — §2-3. 앰버 브랜드 글자를 유지할지가 갈림길이다.
2. **끝단 깃털(B안)** — 하드 컷이 거슬리는지는 실물을 봐야 안다. A안 먼저 보고 결정.
3. **`saturate(140%)`** — 앰버가 과하면 120%. 이건 취향이라 수치로 못 정한다.
