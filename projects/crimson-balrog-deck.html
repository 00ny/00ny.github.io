← 부결

차수는 오르지 않음

발록 마릿수 = 소환 표 수. 마릿수 자체가 공개 정보이므로 별도 숫자 표시가 필요 없음
판정 산식 — 공개 투표는 「투표자 과반」
유효표 = 승인표 + 거부표 (기권 제외)
유효표 == 0  →  부결
승인표 × 2 > 유효표  →  승인
그 외 (동수 포함)  →  부결
기권이 분모를 줄이므로 기권은 승인 문턱을 낮춤. 그래서 기권 역시 전원에게 공개되는 것이 견제 장치임

5. 의사결정|구현이 기획을 되돌린 2건17
지시를 그대로 따르면 깨지는 자리를 찾아 되돌려 보고했다
규칙 두 개가 서로를 깨는 것을 구현 단계가 잡아내 기획으로 되돌린 사례 2건
CASE C · 구현 → 기획  |  「잠금」을 옮기지 않고 지웠다
지시 — 「잠금의 방아쇠를 시작 버튼으로 옮겨라」
충돌 — 로비는 방이 시작됐는지 관측할 수단이 없음. 구 「정원 참 = 잠금」 래치를 그대로 두면 대기 중 한 명이 나간 5/6 방이 영영 못 채워져 갇힘
다시 보니 잠금은 중복이었음시작 조건이 재적 = 정원이므로 시작된 방은 항상 만원이고, 만원인 방에는 이미 못 들어옴
래치를 지우고 강제를 방 안의 문지기로 옮김
CASE D · 구현 → 기획  |  준비 체크를 넣지 않았다
규칙 ① 「방장 외 전원 준비」가 시작 조건?
규칙 ② 방장 유예는 「정원이 찬 시점부터」 돈다?
두 규칙이 서로를 깬다 — 남이 준비를 안 눌러 방장이 시작할 수 없는 동안에도 유예가 흐름. 방장의 잘못이 아닌 이유로 권한이 넘어감
준비 체크 M1 미도입으로 판정규칙표 반영은 아직 미완 — 문서 정합 대기
규칙표에 적혀 있던 항목을 지우지 않고 「미도입 · 사유」로 남김. 지운 자리에 새 결정을 덮어쓰지 않고 번복으로 표시하는 편이, 나중에 같은 논의가 열렸을 때 훨씬 빨리 끝남
이 2건이 증명하는 것

구현이 기획의 하위 공정이 아니라, 규칙의 정합성을 되짚는 검산기로 돌아오게 둔다.

→ 실측이 그대로 기획서로 돌아오는 루프를 만들어 두면, 문서 위에서는 보이지 않던 규칙 충돌이 코드가 아니라 규칙표에서 해소된다. 되돌린 근거는 폐기 논거와 함께 계보로 남긴다.
